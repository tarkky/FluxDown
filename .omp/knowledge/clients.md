## GPUI PC 客户端（`crates/`，三进程本机链路）

**桌面发行物为 GPUI**：Windows / macOS / Linux 发布 `fluxdown-desktop → fluxdown-agent → fluxdownd`，浏览器中继为 `fluxdown_nmh`（`.github/workflows/release.yml` 与 `scripts/package_gpui_{linux,macos}.sh`）。移动端为 `mobile/Android` 与 `mobile/FluxDown`，经 `native/mobile` 的 UniFFI 连接 Rust 核心。GPUI 关于页与服务版本取 `fluxdown_protocol::APP_VERSION`：正式构建由 tag 注入 `FLUXDOWN_APP_VERSION`，本地回退 crate 版本，见 `ops.md`「发布与 CI」。

GPUI 关于页更新说明（`crates/settings/src/sections/about.rs`）按 `i18n::system_locale()` 筛选 release body 的 `fluxdown:lang:zh/en` 区块：中文系统显示中文，其余系统显示英文，不跟随手动设置的界面语言；缺少目标翻译时显示已有语言，无标记的历史说明保留原文。

GPUI 下载设置的 User-Agent 在 `sections/user_agent.rs` 自渲染整行：标题/说明与预设下拉优先同行，按卡片实际可用宽度 flex-wrap，空间不足时下拉移到下一行；仅自定义模式在下方显示占满卡片宽度的输入框。复用设置页字号、间距和控件宽度档位，保留标题/说明搜索元数据；不按窗口单双列写死断点，也不把长输入塞进右侧控件列。

依赖方向固定为 `i18n` / `theme` / `icon_pack` → `components` → `shell` / capability crates → `app`。`app` 只做窗口与单一 agent 会话装配；capability 之间不互相依赖。

- `i18n`：`build.rs` 自动嵌入共享 `assets/i18n/*.json`；locale 规范化、英文键级回退、空值回退和插值契约跨端一致。
- `theme` / `components`：主题 v2（`crates/theme`）。**文件格式 `ThemeDocument` 与运行时解耦**：wire 只含字符串/数字，camelCase，全字段可选、未知键原样保留，`schemaVersion`=2（更高版本 best-effort 加载 + 诊断；v1 内部格式与 Flutter FluxThemeJson 自动迁移/适配），单字段非法只回退并记 `Diagnostic`，绝不整体失败。解析顺序 `<mode>` 层 > `tokens` 共享层 > `extends` 内置基底 > 注册表默认表达式（`Ref`/`RefAlpha`/`Mix`/`Literal`/`Contrast`——保持色相只调亮度直到 WCAG 对比度达标，Rust `extended.rs::with_min_contrast` ↔ TS `value.ts::withMinContrast` 逐步 f32 镜像），越界 clamp、循环引用回退。**唯一事实源 = `registry.rs::TOKENS`**（颜色/圆角/间距/排版/阴影 + 扩展色、状态色、进度色、`stroke`、`focusRing`、`icon`、`density.*` 高度、`components.*` 组件圆角）；`kitBound` token（input/dialog/menu/tooltip 圆角）只跟随 `radius.md/lg`（gpui-component 限制）。运行时 `FluxThemeState::{tokens,extended,density,components}()`，业务 crate 禁写形状/高度/边框字面量，一律读 token；强调色、亮色主色对比度（`ensure_primary_contrast`）、ui_scale 仅运行时生效。正文基线 `typography.sm` = 13/18。新增/改名 token：只加不改，改名走 `migrate.rs` 声明式 rename，重跑 `cargo run -p fluxdown_ui_theme --example gen_theme_registry`（产出 `website-v2/src/lib/gpui-theme/registry.json`、`website-v2/public/schemas/gpui-theme.v2.json`、`crates/theme/tests/fixtures/*.resolved.json`，测试守卫漂移）；已发布版本的 fixtures 永久保留。theme 同时把 DataTable 投影为无网格、面板分隔把手投影为 hairline。
- 主题库：设置「外观」导入（多选 JSON，诊断汇总通知）/导出（仅差异 / 完整）/删除。**唯一事实源 = agent 偏好** `appearance.custom_themes.<编码 id>`（值为主题文件原文，`fluxdown_protocol::custom_theme_key`：规范 id `[a-z0-9_]` 段以 `-` 相连、≤64 字节，`-` 编码为 `.`；原文转义后 ≤64 KB = 云端单值上限），逐主题随配置同步（「外观」分组含集合范围键 `appearance.custom_themes`，本机专属按范围键作用于全部主题）。`settings::theme_library`：导入 = 解析 + 按 `meta.id` 清洗分配 id（冲突加 `-N`）+ `set_pref`；删除 = 写 `null` 墓碑；注册 / 注销只由 app `apply_preferences` → `sync_theme_library`（先于外观投影，原文不变不重解析）完成，云端增删改与本机操作同一路径。旧版 `<data_root>/themes/<id>.json` 由 app `legacy_themes.rs` 在首个快照后一次性迁入偏好，agent 确认后删文件（同 id 原文冲突 / 超限的保留）。偏好 `appearance.{dark,light}_theme` 取 `builtin:<id>` 或 `custom:<id>`（缺失 id 回退该槽位内置默认）。
- 图标：`components::FluxIcon`（Lucide 1.48.0 子集，ISC，线宽 1.75，实现 `IconNamed`，资源由 `ComponentAssets` 提供、app 组合进 `DesktopAssets`）；gpui-component 自带 ~99 个图标语义不全，文件类型 / 任务状态 / 新增图标一律走 FluxIcon（新增：下载 SVG 到 `crates/components/assets/icons/` 并登记 `flux_icons!` 表）。`components::category_icon` 是分类图标唯一映射（侧栏与设置分类编辑器共用）；会刷新的数字统一 `font_features(tabular_numbers())`（界面字体数字为比例宽）。
- 字体：GPUI 用系统默认界面字体，不内嵌字体文件——内置主题 `typography.sans` 为哨兵 `system-ui`（`theme::SANS_FONT_SENTINEL`），运行时换成 gpui 的 `.SystemUIFont`（macOS 系统字体、Windows 系统界面字体如微软雅黑 UI / Segoe UI）。共享 `assets/fonts/MiSans-*` 仍供 Web SPA 使用；它是约 7.7k 字形的子集（缺繁体、`·` 等），曾导致 Windows 上缺字逐字回退雅黑、同一行大小粗细不一，GPUI 不得再引入。桌面字体选择框创建时自动读取本机字体，无手动读取按钮；`Select` 用 `Size::Large` 取得 1rem 字号（选择框、搜索框、列表一致），高度独立设为 `density.control` 并清零纵向内边距，禁止把高度像素传给 `with_size`（会同时放大字号）。
- 字体大小：设备本地偏好 `desktop.font_size`（整数 px 正文字号，界面缩放前，10~24；缺失/`null` 跟随主题；不进同步目录，Web 不镜像——浏览器自带缩放）。倍率 = 所选字号 / 主题 `typography.sm.size`，与 `ui_scale` 相乘。`theme::fonts::fit_text` 在安装主题时按倍率缩放全部排版角色，再把行高抬到不小于「界面/等宽字体自然行高（ascent+|descent|）× 字号」，并把承载文字的 `density.{control,navRow,statusBar,statusControl,sectionHeader,taskRow,taskRowCompact}` 按行高增量加高（只增不减；`toolbarButton`/`titleBar`/图标/间距/圆角不变）。业务代码规则：含文字的高度一律由排版 / 密度 token 推导（不写 `px` 常量）、`text_size` 必须配同角色 `line_height`；装文字的定宽（标签列、定格式数字列）用 `FluxThemeState::text_extent(base)`；虚拟列表行高须随主题刷新，不得构造时缓存。
- 控件套件（`components/src/kit.rs`，所有窗口必须用）：控件高度取 `density.control`（默认 28）：带文字按钮 / 输入框 / 下拉（outline + `dropdown_caret`）/ 数字输入一律 `.control(cx)`（`Input` 的高度必须走 `Styled::h`——它自带的同名 `h()` 只作用于多行，单行会静默退回 26px；gpui-component 按钮字号由 `Size` 写在内部 label 上，故套件用 `Size::Medium`，业务禁止 `.small()/.xsmall()`/自定义高度）；纯图标按钮 `.control_icon(cx)`，chrome 区用 `toolbar_action_button`；标签页一律 `segmented_tabs`（不用 `TabBar`/自造按钮组）；复选框一律 `check_mark`/`check_row`（不用 gpui-component `Checkbox`）；对话框标题 `dialog_title`、底栏 `dialog_footer(cancel, ok, DialogIntent, cx)`（取代 `DialogButtonProps`，其默认按钮 32 高且默认不显示取消）；卡片 `card`（surface + hairline + `components.card.radius`，无阴影）。theme 把 gpui-component `background` 投影为 `surface`（对话框/输入框白底）。
- 强调色落点：选中导航（侧栏/设置/活动栏/RSS）只给图标上强调色 `colors.navSelectedIcon`（≥3:1，统一经 `components::nav_icon_color`），文字 `navSelectedForeground`、底色仍中性 `navSelected`；下载中有任务时状态图标同色；链接 / 限速生效 / `ButtonVariant::Link` 用 `colors.accentText`（与 surface ≥4.5:1）；光标 `caret`、选区 `textSelection`、拖放 `dragBorder`/`dropTarget` 均为 token。gpui-component 派生色（caret/selection/link/list_active/progress_bar/slider/drag/drop/table…）在 `theme/manager.rs::project_onto_kit` 统一重写（`ComponentTheme::change` 按库默认 neutral primary 推导，不重写就停在黑/灰）；新增库控件读到的派生色必须补进这里。悬停与大面积底色永不上强调色。
- `shell`：只拥有窗口 chrome、路由与内容槽，不知道下载、设置、账户、RSS 或扩展。主窗口统一顶栏高 `density.titleBar`（默认 40，不随 ui_scale 缩放，交通灯按它垂直居中；Windows/Linux 为 logo + `AppMenuBar` + 自带窗口按钮），`ShellRoute::with_title_bar(view)` 让活跃路由往顶栏挂插槽；插槽内可交互元素必须拦截左键 `mouse_down` 冒泡，空白处保持拖拽/双击。活动栏、侧栏、顶栏、状态栏同为 `chrome` 底，内容区 `surface`。
- 下载页布局：顶栏插槽 `components/title_bar.rs::DownloadTitleBar`（左：主按钮新建，左缘与内容区（侧栏右侧）对齐——`DownloadView.content_left` 与插槽自身左缘均由 `title_bar::left_edge_probe`（`absolute().inset_0()` canvas）在 prepaint 测得，差值作可收缩的前导留白，前导区更宽时贴插槽左缘；右：搜索、「视图」弹层：列/分组/排序/密度/详情面板）；批量操作只在选中 ≥1 时以内容区底部浮动选择条出现（`selection_bar.rs`，依赖 `SelectionSummary{count,any,any_local,any_active,any_resumable}`）；状态栏只放全局速度、全部暂停/开始、限速、代理快速切换、完成后关机、剩余空间。任务表：文件名列按容器宽回算吸收剩余宽度（不可手动拖宽）；表头排序由 `render_th` 自绘（只在当前排序列显示箭头）；选择列平时显示系统文件图标（舒适 24 / 紧凑 16）、悬停/有选中时换复选框；行悬停浮出单行操作，舒适密度且停靠详情面板未打开时末尾多一个「详情」（`RowAction::Detail` → `DownloadView::show_row_detail`：先单选该行再开面板，否则面板的「跟随单选」会切回旧选中项；面板打开后单击行即切换详情，按钮隐藏）；已完成不画进度条，只有下载中（primary）与失败（destructive）着色；紧凑 30 单行 / 舒适 44 双行。侧栏状态项用语义图标（非文件夹），悬停状态项时图标位换成分类展开箭头（不占额外缩进列），分类子项仅比父项多缩进 `spacing.lg` 且悬停/选中底色铺满整行，计数为 0 不显示。
- footer 代理选择器（GPUI `downloads/components/status_proxy.rs`，Web `downloads/statusbar/ProxyControl.tsx`）：复用设置页的 `none/system/manual/auto`，只增量写 `proxy_mode`，保留已保存端点与认证；手动项显示服务器端点，不显示 URL userinfo。手动服务器或有效端口未配置时禁用该项，并提示「请先在设置中配置代理」；设置页仍可进入手动模式填写配置，footer 不擅自改写已保存模式。配置回流更新当前模式与可选状态，断线禁用，失败复用下载页错误横幅；系统代理指下载服务宿主的系统设置，Web 不读取浏览器电脑的代理。
- 文件图标包（`crates/icon_pack` 包 `fluxdown_ui_icon_pack`，与主题解耦：主题只给单色图标着色，图标包决定形状、彩色包自带配色）：偏好 `appearance.file_icon_pack`（同步目录「外观」组，值 `builtin:<id>` / `custom:<id>`，`fluxdown_protocol::is_icon_pack_ref` 校验；缺省 `builtin:system`）。文件格式 `fluxdown.icon-pack` v1（`format` / `schemaVersion` / `meta` / `extends` / `icons{mode:mask|color, svg, light?, dark?}` / `fileNames` / `fileExtensions` / `kinds` / `default`），内置包与将来的用户包同一格式、同一容错解析（单字段非法只丢弃 + 诊断，SVG 拒收脚本 / 外部 href / `url()` / 事件属性 / 实体，单个 ≤64 KB）。匹配：精确文件名 → 扩展名（复合优先，`tar.gz` 先于 `gz`）→ 大类；沿 `extends` 链取第一个具体匹配，都没有才用第一个 `default`，链尾恒接 `builtin:lucide`。`builtin:system` 是无包文件的链环节 = 下面的系统图标，取不到（Web / 远程 / agent 失败）时用其后的包。内置包 `assets/icon-packs/{lucide,material,catppuccin}.json` 由 `bun scripts/gen_icon_packs.ts` 从上游锁定版本生成（Material Icon Theme npm `5.39.0`，VS Code 安装量第一；Catppuccin Icons `v1.26.0`，暗 mocha / 亮 latte；均 MIT，许可证文件同目录），扩展名 → 大类表 `assets/icon-packs/kinds.json`（`FileKind::of_name` 与 Web `fileKindOf` 共用，替代两端手写表）。GPUI：`IconPackState` 全局只由 app `apply_preferences` → `apply_icon_pack_preference` 改（变化时 `refresh_windows`）；单色 `svg().path()`（`IconPackAssets` 按内容哈希路径 `icon-packs/<hash>.svg` 供字节），彩色按物理像素经 `SvgRenderer` 栅格化后 `img()`（`use_asset` 去重，栅格中留空）。设置「外观 → 主题」组末尾为图标包卡片（样例文件预览）。用户图标包库（导入 / 删除 / 同步）尚未落地，`custom:` 引用当前一律回退缺省选择。
- 系统文件图标（`crates/downloads/src/components/file_icon.rs`，任务表选择列 + 进度窗口 + 拖拽预览共用 `task_file_icon` / `named_file_icon`，所选链含 `builtin:system` 时生效）：经 `DownloadsCommand::FileIcon` → `agent.platform.fileIcon` 取资源管理器 / Finder / GTK 图标主题的 PNG（`crates/*` 零 unsafe，提取在 agent，见 hosts-and-api.md）；GPUI 资产缓存 `Window::use_asset` 按「扩展名 + 物理像素」去重，`FILE_ICON_PER_FILE_EXTENSIONS`（`exe`/`ico`，图标内嵌在文件里）在本机产物存在时按路径 + 完成时间取；请求中留空（不先闪回退图标），取不到（agent 不支持 / 失败，结果本会话缓存不重试）用链上下一个包的图标；文件丢失时图标 50% 透明。端口经 `install_port` 以 GPUI Global 注入（`DownloadView::new`），全部下载窗口共用。
- 下载任务行交互：表格 `row_selectable(false)`，gpui-component 的 `TableEvent::DoubleClickedRow` 永不触发——双击由 `task_table.rs::render_tr` 自挂的普通 `on_click`（`click_count()==2`，不占用表格实体）回调 `DownloadView::activate_row`：本地已完成且文件仍在 → `agent.platform.openTask`，其余（含文件已丢失）→ 停靠详情。文件跟踪：`DownloadsController` 消费 `WsServerMsg::FileMissingChanged` 就地改行（`DownloadTaskView::{is_file_missing,has_local_file}`），状态列显示 `statusFileMissing`（warning 色），「打开文件」（行操作 / 右键 / 选择条 / 双击）只对 `has_local_file` 生效；主窗口获焦发 `daemon.task.rescan`（`model/file_rescan.rs` 10s 节流 + 尾沿补发），打开失败 / 拖出时发现文件不在立即重扫，daemon 300s 定时扫描兜底。拖出：`components/task_drag.rs` 对 `has_local_file` 行挂 `on_drag` + `external_drag_payload`（锚点在选区内则带整个选区，拖出窗口时逐个 `metadata` 探测，目录按目录交出）；gpui-pre 仅 macOS / Linux Wayland 实现平台拖出，Windows / X11 拖出窗口无动作（补 Windows 需新依赖或 fork gpui-pre-windows，2026-09-29 用户决定暂不做）。
- 任务行右键：选中（未选中行 → 单选该行；已在选区内 → 保持选区）必须在 `TableDelegate::context_menu` 内完成，不能放在 `TableEvent::RightClickedRow` 订阅里——gpui-component 的 `ContextMenu` 在鼠标冒泡阶段先 `window.defer` 排队构建菜单，行监听随后才 emit 事件，effect FIFO 执行，订阅者收到时菜单已按旧选区建好（无选中 → 空菜单不弹、只剩复选框常显；已选他行 → 菜单作用于旧选区）。`right_clicked_row` 在派发时同步写入，构建期可靠。
- 下载选择条的删除菜单提供「清理无效任务」（`crates/downloads/src/components/selection_bar.rs`）：只处理选区中的失败任务、已完成且文件跟踪标记丢失（删除或移走）的本地任务；远程只接受明确的 failed，不将 canceled / 未知状态归入清理。空候选或断线禁用；确认框显示候选数量，确认时固定原候选并按最新状态重新筛选，全部复用仅删记录的批量删除路径（`delete_files=false`），保留文件及残片。
- `downloads` / `settings` / `account` / `rss` / `extensions`：各自拥有视图模型、controller 与 capability-local port；只消费 `fluxdown_protocol` DTO。
- 新建下载的通用插件清单（`downloads/pages/new_download/preview.rs` → `pages/manifest*.rs`，纯模型 `model/manifest.rs`）：本机单个 GET 链接先只读预解析；有清单才在原窗口切换文件选择，空结果 / 失败沿用原单任务路径。取消预解析及返回表单不建任务，代际隔离拒绝迟到回调；建组失败留在清单重试。默认全选插件返回的全部文件，不按平台 / 剧集 / 文件名推断或合并；只有 `item.variants` 非空时提供规格下拉，显式选择才提交 `<itemId>@<variantId>`，插件默认仍提交原 `itemId`。搜索、扩展名筛选、目录三态和导航、有效大小统计、保存目录 / 队列 / 立即或稍后沿用现有清单语义。外部捕获走 agent 私有上下文的只读预解析与成功后消费的建组 RPC，浏览器请求秘密不进入清单 DTO；多链接、远程下发、POST / body / 独立音轨及静默链路不强行切入此交互流程。
- 组件管理（GPUI `extensions/pages/managed_components.rs`）：FFmpeg / yt-dlp 手动路径输入框按桌面目标平台选择示例，Windows 使用盘符路径与 `.exe`，macOS / Linux 使用各自的 POSIX 路径；示例不改写已配置的组件路径。

- 下载页多设备（`downloads/src/model/{devices,dispatch}.rs` + `submission.rs`）：「其他设备」= `cloud_devices` 去掉 `is_current`（本机 id 取会话 `device.device_id`，名册 `is_current` 兜底）+ 已配对设备（指纹），按 id 去重、同名追加末 4 位短码。侧栏设备区（`全部设备`/本机/其他设备，在线状态点）与表格筛选/计数共用 `SidebarSelection::device_matches`——远程任务按 `to_device`（任务实际下载的设备，不是 `from_device`）匹配，`to_device == 本机` 的云端镜像行在 controller 里过滤掉（本地已有真实任务）；`SessionChanged(None)` 清空设备与远程任务并重建选择。默认可见性 = 存在其他设备；「隐藏此区块」与设置页开关都写设备本地偏好（`SetLocalPreference`，`ui.show_sidebar_devices` 不入同步目录）。远程任务命令一律 `RemoteCommandParams`（`delete` 带 `deleteFiles`，确认框与本地删除同语义），`RemoteTaskStatus::Unknown` / 状态不适用的动作不发命令；批量失败按 `reason` 显示且不被后完成的成功覆盖。新建下载「下载到」：本机/云设备（离线可选并提示上线后执行）/已配对设备，上次目标存设备本地偏好 `download.last_target`；选远端后保存目录输入独立于本机目录（占位 = 目标 `default_save_dir`，空 = 目标默认目录，提交按目标 `effective_path_style()` 校验绝对路径），本地目录选择 / 分段 / 队列 / 稍后下载 / 高级选项（Cookie、代理、认证…）/ 种子文件都不适用；提交经 `run_submission` 逐条 `agent.remote.dispatch` / `agent.link.dispatch`，汇总提示（全成功 / 部分成功 / 失败带原因）在主窗口下载页与无主窗口直提交两条路径共用；外部捕获进入的表单同样可选目标（下发后忽略对应待确认捕获事务）。

- **GPUI 动效**（`crates/components/src/motion.rs`）：框架能力 = gpui 核心 `with_animation`（时长 + 缓动，按元素 id 计时）/ `with_spring`、gpui-base `transition` / `spring`（按 id 可打断重定向，带速度）/ `Presence` / `MotionReveal`、元素级只有 `opacity`（**按图元相乘**，不是整组合成）与位置 / 尺寸 / 颜色 / 阴影插值；div **没有** transform（缩放 / 旋转只对 svg 图标），gpui 的 `.hover()` / `.active()` 是静态样式、无过渡。节奏统一取 gpui-component `MotionTokens`（`duration_fast/normal/slow`、`easing_enter/move`、`spring_move`），`cx.reduce_motion()` 由 gpui-base 从系统读取，上述 API 自动落到终态。应用自有原语：`StateLayer`（按钮第一个子元素，悬停 / 按下 / 选中底色淡入淡出，宿主不再 `.hover()` / `.active()` 改底色；**选中项的悬停 / 按下层改用选中色而不是撤掉**，否则点选瞬间按下层消失、选中层刚从 0 淡入，露出空底形成闪烁）、`SlidingHighlight`（活动栏选中块、`segmented_tabs` 白底的弹簧滑块）、`color_transition`（选中文字 / 图标色）。**不做内容 / 页面淡入**：从底色淡入在切换瞬间先显示纯色遮罩（白闪），页面含侧栏 + 内容区多种底色时单色遮罩必然串色；真正交叉淡入需同时绘制新旧两页并逐帧改透明度，按图元相乘的透明度还会层叠透视。**gpui-fast 取舍**：动画帧重建请求帧的 view，故状态层做成挂在元素状态里、不被父 view 观察的小 view（`detached_view`；`use_keyed_state` 会让父 view 观察并跟着重建），所在页面继续复用上一帧。gpui-component 的 `Button`（对话框底栏、大部分工具栏按钮）悬停 / 按下仍是其内置静态样式，本层无法注入过渡。

### 云端连接与设备在线状态

PC 与 Web SPA 都消费 agent 的 `AgentSnapshot.cloud_connection` / `CloudConnectionChanged`（Web wire 为 `cloudConnection`），不自行连接 FluxCloud。它表示远程任务事件通道，与登录会话、本机 UI→agent 连接、daemon 下载核心连接及配置同步的 `sync.connected` 分别独立。

- `is_current` 只表示设备身份；登录或刷新资料成功不代表设备在线。
- 只有本机 agent 投影新鲜且云通道为 `connected` 时，才把设备名册中的 `is_online` 显示为在线/离线。断连时账户列表、详情、在线计数和下载目标显示状态未知，不保留旧绿点；LAN 状态只受本机 agent 连接影响。
- 设备区在云通道不健康时调用 `agent.remote.reconnect` 后刷新名册；响应 `{accepted:true}` 仅表示已请求重连，最终状态由事件驱动。健康时普通刷新不重建 SSE。
- 云设备离线或未知仍可下发排队任务，不据此禁用目标。顶部账户刷新仍只是资料/名册刷新。

### 开机自启与旧版迁移：agent `platform/autostart.rs`

## 原生 iOS（`mobile/FluxDown`，SwiftUI · Liquid Glass）

当前 iOS 客户端，与 `mobile/Android` 共享同一 Rust 核心（`native/mobile`，UniFFI）与同一分层；视觉遵循 Apple 官方设计（设计稿 `docs/mobile-ui/ios/*`，本机草稿）：系统组件优先，Liquid Glass 只用于浮在内容之上的功能层（标签栏 / 底部附件 / 工具栏 / Toast / 范围条），内容卡片不叠玻璃；底栏主操作统一 `ToolbarItem(.bottomBar)` + `.borderedProminent`（系统渲染着色玻璃），不在工具栏项或内容里再用 `.glass*`。最低 iOS 26.1（`tabViewBottomAccessory(isEnabled:)` 所需：页面自带底栏或隐藏标签栏时经 `suppressesBottomAccessory` 隐藏活动附件；Xcode 27 / iOS 27 SDK；iOS 27 API 仅在壳层用 `#available` 渐进增强，如 `Tab(role: .prominent)` 新建标签）。全局搜索不是标签：各根页右上角按钮以 `SheetRoute.search` 呈现。

- **包结构**（本地 SwiftPM 包 `FluxKit`，与 Android 模块一一对应）：`FluxDomain` = `:core`（模型、`HostSession` 端口、`HostStore` reducer、`Format`、`L()` 文案、`Protocol/` 通用通道）；`FluxBridge` = `:bridge`（`RustHostSession` 适配 + `Mapping.swift`；进程级 `FluxBridge.openLocal/openRemote/shutdownLocal`）；`FluxRustBindings`（UniFFI 生成 Swift，只被 FluxBridge `internal import`，生成的 `HostSession` / `FluxCore` / `*Dto` 不外泄）；`FluxUI` = `:fluxui`（纯组件库，不依赖 FluxDomain：色彩令牌 `Color.fd*` 是唯一字面量处、分段图谱 / 速度波形 / 圆环按钮 / KindIcon / Toast / 范围条…）。模型避开 Swift 并发库重名：`DownloadTask`、`DownloadGroup`、`TaskQueue`、`TaskCategory`。
- **图标 / 版式约定**：SF Symbols 经 `FluxUI/Theme/FluxSymbol.swift` 语义注册表（同一概念全 App 同一符号；出现在两处以上的概念必须走它）。只用当前名称（不用 `doc.on.doc` 等已改名别名）、最低可用版本 ≤ 26.1；**不用 Apple 受限符号**：`icloud*`（FluxCloud 用 `cloud`）、`person.badge.key`（仅通行密钥）、`macbook.and.iphone` 等产品图形，`iphone` / `ipad` 只指本机（`FluxSymbol.thisDevice`），其它手机用 `smartphone`。图标扁平：设置分类方块纯色底（系统「设置」同款）、`KindIcon` 类别色淡底 + 类别色符号，不加渐变 / 高光 / 投影。标签根页标题统一 `rootNavigationTitle`（`.inlineLarge`：大字标题与工具栏同一行；副行 = 当前主机 · 连接状态，标题菜单 `HostTitleMenuItems` 切主机），根页搜索框 `.navigationBarDrawer(.automatic)` 下拉出现；根页右上角至多「全局搜索 + 一组动作」，次要动作收进 `ellipsis` 菜单。阅读型滚动内容（设置、设备、任务详情）挂 `readableContentWidth()`，iPad 宽窗口两侧留白不拉满。App 图标 = `FluxDown/AppIcon.icon`（Icon Composer 格式，单层白箭头 + 品牌蓝自动渐变底，系统渲染 Liquid Glass 与深色 / 着色 / 透明外观；`ictool` 可离线导出预览）。
- **启动画面 / 启动揭幕**：Info.plist `UILaunchScreen` = `UIColorName: LaunchBackground`（colorset = `systemGroupedBackground` 明暗两值，随**系统**外观）+ `UIImageName: LaunchMark`（logo 品牌蓝箭头、保留 400 单位画框，112pt，`gen_icons.ts` 生成）。`RootView()` 直接挂 `.launchReveal(markSide: 112)`（必须在注入 `fluxAccent` / `preferredColorScheme` 的外层修饰符之内；`FluxUI/Brand/LaunchReveal.swift`，与 Android 同一「箭头开窗」编排、每进程一次、不参与命中测试；减弱动态效果退化为 0.2s 淡出）。跟随主题：首帧按场景（系统）外观解析的启动底色 + 品牌蓝，吸气段过渡到按 App 外观解析的 `systemGroupedBackground` 与 `fluxAccent`。iOS 没有 Android 那样的「系统画面退场」回调，onAppear 又早于首帧提交：揭幕先停在与启动画面一致的首帧，等主线程连续 3 帧不卡顿再开始（至多 0.6s）。改 `LaunchMark` 尺寸须同步 `markSide`。揭幕后下载页占位行（`DownloadRowPlaceholder`）图形用 `.quaternary` 填充并呼吸（同 Android 骨架），首个快照到达时列表随 `loading` 平滑切换。
- **通用通道**（覆盖 `fluxdown_protocol` 全部 `daemon.*` / `agent.*`，类型化 UniFFI 面只是其子集）：`HostSession.call(_ method:, params: Data?) async throws(HostError) -> Data`（Rust 侧 `HostSession::call(method, params_json)`，前缀只放行 `daemon.` / `agent.`，参数非法 JSON → `.invalidArgument`，排队 / 超时语义同其它命令）；类型化扩展 `call<R: Decodable>(_:params:)` / `call<R>(_:)` / `callVoid(_:params:)` / `callVoid(_:)`（编解码失败 → `HostError(.internal)`）。JSON 形状 = 协议 serde wire（camelCase，同 Web SPA `web/src/lib/rpc/protocol/*.ts`）。`FluxDomain/Protocol/`：`ProtocolJSON`（共享 coder + 错误映射）、`JSONValue`（任意 JSON）、`WireStringEnum`（宽松枚举：未知值落入 `unknown(String)` 不崩溃）、`Methods.swift`（`HostMethod` / `HostCapability`，与 `method.rs` 一一对应）、`HostSections.swift`（`HostSection` / `HostNoticeName`，与 `native/mobile/src/sections.rs` 一一对应）；各领域 Codable DTO 放 `Protocol/<Area>.swift`。**分区**：`HostSnapshot.sections: [String: Data]` 携带类型化 DTO 之外的每个 `AgentSnapshot` / `DaemonSnapshot` 字段（键 `agent.<serde 字段名>` / `daemon.<serde 字段名>`），`HostEvent.sectionChanged(name:json:)` 仅在该分区序列化结果变化时下发（空操作不下发，整表替换改发 `.snapshot`）；`HostState.sections` + `section(_:as:)` 解码，结构性立即发布。**通知**：`HostEvent.notice(name:json:)` = 一次性、不进快照（`sessionRevoked`、`captureTasksStarted`、`taskActivityAdded` 与被类型化投影丢弃的引擎消息 `pluginAutoDisabled` / `duplicateTorrent` / `pluginHookActivity` / `rssItemsChanged` / `rssFeedValidated` / `componentProgress` / `componentResult` / `linkIncomingPairing` / `taskCdnEvent`），`HostStore.notices`（最近 50 条，`id` 单调递增，观察者记住已处理 id 即不漏不重）。
- **App 层**（`mobile/FluxDown/FluxDown/`，Xcode 同步文件夹，Swift 6 + 默认 MainActor 隔离）：`App/AppContainer`（主机列表 / 切换 / 添加远端主机，切换顺序同 Android：detach → 关旧会话 → attach）、`App/HostRepo`（远端主机列表存 UserDefaults，访问密钥存钥匙串 `AfterFirstUnlockThisDeviceOnly`）、`Navigation/AppRouter`（单一导航状态 + 全局 `SheetRoute`）、`Actions/TaskActions`（任务动作唯一分发点，菜单顺序沿用 PC `MenuEntry`）、`Shell/RootView`（TabView + 底部活动条 + Sheet 路由 + 选择请求排队 + 链接唤起）、`Features/*`。

- **下载列表里的远程任务**（对齐 GPUI 下载页远程行 `DownloadTaskView::remote`；与 Android 同一契约）：`DownloadsModel` 从 `agent.remoteTasks` 分区取云端下发任务（主机有 `agent.remoteTasks` 能力时；去掉 `toDevice == 本机` 的镜像，本机 id = 会话设备 → 名册 `isCurrent`），经 `DeriveInput.remote` 进 `DownloadsDeriver`，与本机任务合并进**同一个列表**（`DownloadsSection.rows: [DownloadsRow]`，`.task(TaskItem)` / `.remote(RemoteRow)`，远程行 id 加 `remote:` 前缀；没有单独的末尾分区）。计入状态文件夹（等待 / 已接单 / 未知 / 下载中 → 下载中，失败 / 已取消 → 失败）、分类（按显示名）、搜索（名称 / URL），队列或任务组范围下不出现。**统一排序**：本机与远程投影成同一个 `SortProjection` 走同一个比较器（智能档 / 创建时间 / 名称 / 大小 / 进度 / 速度 + 升降序 + 平局按 id；远程档位 下载中 1 · 等待 / 已接单 / 未知 2 · 失败 / 已取消 3 · 暂停 4 · 完成 5，永不 boosted；创建时间 = `createdAt` ISO-8601 → Unix 秒（带 / 不带小数秒，失败 0）；大小 `totalBytes ?? 0`；进度 unknown 视为无；速度终态 0），进度 / 速度键的重排节流位置表同含远程 id。**分区 / 分组**：「传输中」= 本机 pending / downloading / preparing + 远程 pending / accepted / downloading / unknown，分区头计数含远程、汇总速度只算本机；状态 / 日期 / 类型 / 站点（url host）分组与本机同规，队列分组里远程单独一组放最后（`queue:remote`，标题 `remoteTasksGroup`），任务组分组里远程归「未分组」。**筛选**：`DownloadsFilter.remoteOnly` + 分类芯片行末尾的「远程任务」芯片（`remoteTasksGroup` + `FluxSymbol.cloud`，计数 `Facets.remoteCount` = 范围与当前文件夹内的远程数、分类筛选之前；`remoteCount > 0` 或已选中才显示）；与 `categoryId` 互斥（`setRemoteOnly` / `setCategory`），`setFolder` 同时清两者，分类区被 `FilterBarVisibility` 隐藏时复位。渲染复用 `RemoteTaskRow`（`DownloadsRemoteRow`，单独读主机状态，列表 body 不随 10 Hz 重算），`.selectionDisabled()` 且不进 `visibleIds`，不参与多选。命令与在途状态走 `AppContainer.devices`（`DevicesModel` 单例，设备页共用）。局域网直连下发（`agent.link.dispatch`）没有云端任务记录，不出现在这里。
- **文件已存在询问**（`file_exists_behavior = ask`，issue #375）：`SelectionKind.fileExists(FileConflict)` / `SelectionOutcome.fileExists(action:)`（`FluxDomain/Model/FileConflict.swift`，`Mapping.swift` 映射 UniFFI DTO）。所有待答 `fileExists` 聚合进全局路由 `SheetRoute.fileConflicts`（`Features/Selection/FileConflictSheet`：一条 = 卡片 `FileConflictCard`，多条 = 列表 + 底栏批量「全部重命名 / 覆盖 / 跳过 / 取消」，`SelectionResolver.resolveAll` 顺序答复、只对允许该动作的请求生效）；不再走 `.selection(requestId:)`。划走 / 「稍后决定」只记入 `dismissedSelections`（不发 RPC，主机 60s 超时按重命名）；`conflict` / `notFound` 视为已被解决静默放弃，其它错误保留行并 toast 让用户重试。下载页横幅聚合为一条（最早到期），任务行 `TaskItem.awaitingDecision` 显示「待确认」角标（点角标重新打开）；通知用类别 `fluxdown.fileConflict`，动作标题「自动重命名」= 默认答复（重命名）。

- **Rust 产物**：`scripts/build-core.sh [--release] [--cloud-url URL] [--run]` 编 `aarch64-apple-ios` + `aarch64-apple-ios-sim` 静态库为 `FluxKit/Artifacts/fluxdown_mobileFFI.xcframework`，并从宿主机 debug dylib 的元数据生成 `FluxKit/Sources/FluxRustBindings/fluxdown_mobile.swift`（均 gitignore；改 Rust 必须重跑，否则 UniFFI 校验和不符会在运行期报错）。模拟器仅 arm64（工程排除 x86_64）。FluxCloud 地址是**编译期**写入（嵌入式 agent 只读 `option_env!("FLUXCLOUD_BASE_URL")`，不读运行期环境），未提供时回退 `http://127.0.0.1:8720`（本机 FluxCloud 开发服务；模拟器可达、真机不可达）：`--cloud-url` 或导出 `FLUXCLOUD_BASE_URL` 指定，空串由脚本清除（否则会写入空地址）。脚本只产出 xcframework，**不会更新模拟器里已安装的 App**；`--run` 接着用与 Xcode 共用的 DerivedData 构建 App，并对已启动的模拟器 terminate → install → launch。
- **命令**：`cd mobile/FluxDown/FluxKit && xcodebuild test -scheme FluxKit-Package -destination 'platform=iOS Simulator,name=iPhone 18 Pro'`（reducer 规则 + 真实 FFI 冒烟：回环 HTTP 下载落盘、配置冲突经 FFI 往返）；App：`xcodebuild build -project FluxDown.xcodeproj -scheme FluxDown -destination 'generic/platform=iOS Simulator'`。
- **默认 MainActor 隔离的陷阱（诊断页崩溃）**：App 与 `FluxUI` 默认 MainActor 隔离，SwiftUI 异步渲染线程（`com.apple.SwiftUI.AsyncRenderer`）会在主线程之外比较 / 求值我们的代码；落在 MainActor 上的一致性或闭包会被动态隔离检查拦下（`EXC_BREAKPOINT` · `_dispatch_assert_queue_fail` “Block was expected to execute on queue [main]”）。诊断页在主机诊断结束后崩溃，首要嫌疑是 `.fluxAnimation(.smooth, value: model.host)` 的 `DiagnosticsModel.HostReport: Equatable` 是 MainActor 隔离的 `==`。**规则**：凡 SwiftUI 可能离开主线程比较 / 求值的东西必须 `nonisolated`——动画 / 触感的 `value:` / `trigger:` 类型、`ForEach` / `Picker` / 导航路由 / `sheet(item:)` 的 `Identifiable` / `Hashable` 类型、`Canvas` 渲染闭包（标 `@Sendable`，只捕获主线程先算好的 Sendable 值）、自定义 `Layout` / `Shape` / `Animatable`、`UIColor { trait in }` 动态色 block。纯数据类型写 `nonisolated struct/enum`（需主线程 API 的方法单独 `@MainActor`）；必须留在 MainActor 的 `@Observable` 模型不要整个当动画值，改传 `nonisolated` 投影（版本号 / `id` / `Bool` / 快照）。`FluxDownTests/NonisolatedValueTests` 用 `Task.detached { a == b }` 守住这条线。

## 浏览器扩展（`fluxDown/`）与用户脚本（`userscript/`）

### 扩展（WXT，Chrome + Firefox MV3）
- **通信**：桌面发行链路全平台走 NMH：扩展 →（stdin/stdout）→ `fluxdown_nmh` →（Windows Named Pipe / Linux-mac UDS）→ `fluxdown-agent` → daemon。消息 = 4 字节 LE 长度 + JSON。action：`ping`（只探不拉起）/`download`/`batch_download`（换行 join 单确认，按 700KB+1000 条分块防 1MB 帧上限，旧 App 回退逐条）/`warmup`（本地应答重叠冷启动）。
- **扩展连接诊断导出**：popup 底部与设置页「通用 → 连接诊断」提供「导出日志」，不依赖桌面 App 在线。`utils/connection-diagnostics*` 由 background 单写者串行持久化 NMH 连接失败、浏览器拒绝原因、请求超时/失败、重试和恢复事件；最多 200 条、按最近发生时间保留 7 天，相邻同类事件合并计数，后台重启可恢复。导出时仅 ping 探活（不拉起 App、不建任务），输出扩展 ID/版本、浏览器环境、模式/配置布尔摘要及事件 JSON；不复制完整设置、Cookie、令牌、下载链接、文件名或请求体，浏览器错误中的路径/凭据先脱敏再落盘。日志只在本机保存，由用户手动导出，不自动上传；content script 不可读写诊断日志。此导出与资源嗅探的页面资源调试日志分开。
- **三层拦截**：`onHeadersReceived`（缓存元数据 + Firefox `webRequestBlocking` cancel）→ `onDeterminingFilename`（Chrome 先发起 `downloads.cancel`，再调用 `suggest()` 释放文件名管线；取消成功才投递客户端）→ `onCreated+onChanged` 兜底 + 页面态 `fetch-interceptor.ts`。`suggest` 不支持 `cancel` 字段；取消失败保留原生下载，投递失败仍走既有浏览器回退。重定向下载以 `finalUrl` 为目标，原始 URL 保留用于请求事务缓存查找。
- **IPC 用户隔离**：agent 与中继分别在 `native/agent/src/nmh.rs::{socket_path_under,pipe_name_for}` 和 `native/nmh/src/main.rs` 的同名函数独立推导同一端点，两侧须同步。Unix 唯一 socket 为用户 home 下固定数据目录的 `<data_dir>/ipc/fluxdown.sock`（Linux `<data_dir>` = `~/.local/share/fluxdown/`，macOS = `~/Library/Application Support/fluxdown/`），`ipc` 目录 0700、socket 0600，agent 额外校验对端 uid；Windows 用 `\\.\pipe\fluxdown-<account>`，`USERNAME` 转小写后逐字节编码 `[a-z0-9]` 之外的字符为 `_xx`（下划线也编码），避免账户名清洗碰撞。无法确定 home / 用户名时端点不可用；Unix 不走会在沙箱中重映射的 `XDG_RUNTIME_DIR`。
- **NMH 注册写入**（`native/agent/src/nmh.rs::registry`）：Unix 启动脚本与清单都经「同目录临时文件 + rename」原子替换——旧文件即使属于 root（曾以 sudo 运行），只要目录属于当前用户就能换成用户自己的文件；目录本身被拒时 `register()` 返回 `RegisterIssues.denied`，启动自愈只记日志报错，Doctor「重新注册」请求授权把这些目录改回属主后以普通权限重写。中继属于当前用户却缺执行位时以普通权限补上。
- **资源嗅探**（`media-sniff.ts`）：视频/音频/HLS/DASH/大文件，按 tabId 分组 + badge。
- Chrome ID 经 manifest key 钉住（匹配 NMH `allowed_origins`）；Alt+Shift+D 切换拦截；`Alt+Click` 15s 放行；声明零数据采集。

### 用户脚本（`userscript/fluxdown.user.js`，Tampermonkey）
页面态**扩展替代**（不能/不愿装扩展的用户）。`GM_xmlhttpRequest` POST 到本机 RPC `:17800/download`（带 `X-FluxDown-Client` 头 + 可选 token），拦截 DOM 下载 + hook fetch/XHR/MediaSource 嗅探。局限：无法拦截内核发起（Content-Disposition）下载、仅非 httpOnly cookie。

## Web SPA（`web/`）

- **传输**：`src/lib/rpc/` 是唯一数据面——agent `/rpc` JSON-RPC（子协议鉴权 `fluxdown.rpc.v1` + `fluxdown.token.<b64url>`，hello 声明 `client.selections`）→ `system.snapshot` → `service.event` 按 epoch/sequence 增量应用（`apply.ts` 移植 `native/protocol/src/event.rs`；断档/4009 重同步，`service-quit` 不重连）。`protocol/` 为 wire TS 镜像，`methods/` 提供 `rpc.<system|daemon|agent>.<group>.<method>`，`hooks.ts` 选择器；`http.ts` 管 `/api/web/*`（blob 上传、已完成文件下载、日志 zip）。不再有 REST 管理面或 `/api/v1/ws`。云账户/同步全部走 agent（`agent.auth.*`/`agent.sync.*`），Web 不直连 FluxCloud。
