## HTTP API（`native/api`，`fluxdown_api`）

一个端口（桌面默认 17800 **仅 127.0.0.1**；headless `fluxdown-agent --server` 默认 `0.0.0.0:17800`）、一个 axum 服务器，多组按配置独立启停的路由。agent 宿主：开关经 `agent.gateway.patch` 热更新（`ApiRuntimeSwitches` + `TokenCell`），桌面端口修改先启动同一 router 的新监听并以官方 Bearer `/rpc` 握手验证，再保存配置与端点、停止旧监听；失败保留旧服务，既有官方 WS 与 daemon 下载不因端口切换断开。`lanEnabled` 仍下次启动生效，server / 环境固定监听地址不可在 UI 改端口。

| 路由组 | 端点 | 开关（config 键） | 鉴权 |
|---|---|---|---|
| 探活 | `GET /ping` | 总开关 | 无 |
| 脚本接管 | `POST /download`、`/download/batch` | `local_server_takeover_enabled`（默认开） | `X-FluxDown-Client` 头 + 可选 token |
| aria2 兼容 | `POST /jsonrpc`（36 方法）+ `GET /jsonrpc`（WS 升级，`jsonrpc_ws.rs`：RPC + `onDownloadXxx` 通知推送） | `local_server_jsonrpc_enabled`（默认开） | 可选 token（`X-FluxDown-Token` 或 `params[0]="token:xxx"`） |
| 管理 API | `/api/v1/*`（info、tasks CRUD+pause/continue[all]、queues、resolve/preview、groups CRUD+pause/continue、plugins list/install/install-dev/enabled/settings/**auth**（begin/poll/cancel/logout/status）/uninstall + ignore-plugin-retry、**site-auth** list/save/get/delete（`GET /site-auth/{site}` 回传明文密码，仅定向查询用于编辑表单回填）、market list/install、**rss** CRUD+refresh+items+items/action+validate） | `local_server_api_enabled`（桌面默认**关**；server 强制开） | **强制** token（Bearer 或 `X-FluxDown-Token`） |
| MCP | `POST /mcp`（Streamable HTTP 无状态子集，协议 2025-06-18；12 工具：download_add/list/get/pause/resume/pause_all/resume_all/remove + queue_list + rss_list/rss_add/rss_remove） | `local_server_mcp_enabled`（桌面默认关；server 默认开） | 同管理 API token |
| OpenAPI | `GET /api/v1/openapi.json`（utoipa 3.1，含漂移守卫测试） | 随管理 API | 无 |

- **`ApiHost` trait**（`service.rs`）：必需方法（list/get/create/delete/pause/continue task、pause/continue all、list_queues、submit_external）+ 可默认降级方法（config/plugins/market/groups/resolve_preview/subscribe_task_events/…）。`UNKNOWN_ENDPOINT_MESSAGE` 区分未注册路由 404 与资源 404。
- **鉴权与浏览器门禁**（`auth.rs`、`server.rs::browser_origin_guard`）：常量时间比较；接管需非空 `X-FluxDown-Client` 头；管理/MCP 强制非空 token（403）。默认不返 CORS 头；`/jsonrpc`（POST 与 WS 升级）和 `/download*` 的 `Origin` 仅放行扩展源或与 `Host` 同源的请求，其余 403，堵住不触发预检的简单 POST/WS。不带 `Origin` 的非浏览器客户端不受来源门禁影响。桌面默认绑 127.0.0.1（`local_server_lan_enabled` 可改绑 0.0.0.0）；仅回环监听时所有核心 API 请求的 `Host` 须为 127.0.0.1 / localhost / [::1]，防 DNS 重绑定，LAN/server 模式不强制此限制。
- **桌面对外暴露自动补密钥**（`agent/src/gateway.rs::ensure_exposed_auth_token`、`runtime.rs`）：LAN 或 CORS 任一开启、且接管或 aria2 任一开启时，空用户 token 自动生成并持久化；已有 token 保留，暴露面仍在时显式清空也会补回。启动与 legacy 迁移后同样补齐；headless 不调用该策略，空密钥必须保留为首次设置状态。
- **CORS 豁免开关**（`local_server_cors_allow_all`，默认 false）：开启后 `cors_and_preflight` 对预检与真实响应发 `Access-Control-Allow-Origin: *`（预检另带 `Access-Control-Allow-Private-Network: true`、`Allow-Headers` 回显），等价 aria2 `--rpc-allow-origin-all`，并显式放开上述 `Origin` 门禁，但不取消回环 `Host` 校验或 token 校验。代价是任意网页可探测端口，并在持有 token 时调用兼容 API；aria2 直接建任务、没有确认框，脚本接管也可能按免打扰设置静默建任务，不能把确认框当作通用防线。
- **语义区分**：脚本接管 → 外部下载流程（桌面可确认或免打扰静默建任务；headless 直接建任务）；aria2 `addUri`/管理 `POST /tasks` → 直接建任务返真实 ID（无确认框）。`takeover.rs` 的 batch 两形态合并为单 `DownloadRequest`（url 换行 join）。
- **批量 RPC**（`jsonrpc.rs::handle_jsonrpc/system_multicall`）：aria2 `/jsonrpc` 接受顶层调用数组，逐项顺序执行并逐项返回；`system.multicall` 各子调用各自携带 `params[0]="token:xxx"`（或共用有效 token 请求头），不是只给外层信封放 token。名单方法免 token 鉴权不绕过 headless 首次设置门禁。agent/daemon `/rpc` 一帧只接收一个 `RpcRequest`，并发调用靠独立请求 ID，不接受顶层数组。
- **任务批量变更 RPC**（`protocol/src/{method,daemon}.rs`、`daemon/src/{service,actor}.rs`、`web/src/lib/rpc/methods/daemon.ts`）：`daemon.task.pauseMany/resumeMany {taskIds}` 与 `daemon.task.deleteMany {taskIds, deleteFiles}` 一次提交整批；daemon 去重、忽略未知 ID、空列表为空操作，批处理末尾统一推任务快照。Web 本地任务批量操作复用它们，不逐任务并发挤满 agent 的普通 daemon 通道，也不把这些方法误写成 `/rpc` 顶层数组。
- **配对 v2**（`link/src/pairing.rs`、`protocol/src/daemon.rs`、`api/src/server.rs`）：`/api/v1/link/pair/hello → reveal → confirm`；hello 只提交 `sha256(eph_I || nonce_I)` 承诺，响应方回本次会话的临时值后发起方才 reveal，核对承诺并验证完整转录签名后两端才展示 SAS；双方肉眼核对并批准才入册。版本必须严格相等（当前 2），缺版本按 0 处理并拒绝，不兼容无承诺的旧握手、不降级；reveal 承诺不符或超过 30s 即作废，不能重试旧会话，confirm 不能跳过 reveal。配对路由以一次性码/会话/SAS 而非用户 API token 守卫。
- **aria2 纯映射**（`aria2.rs`）：GID↔task_id 编解码、`METHOD_NAMES`=36、`NOTIFICATION_NAMES`=6、业务错误统一 `code:1`。

## 宿主与客户端 crate

### `native/mobile`（原生 Android/iOS 的 UniFFI 入口）
`FluxCore` / `HostSession` 提供本机与远端主机会话。本机复用进程内 daemon 与 agent 嵌入模式，远端通过 WebSocket `/rpc`；握手、游标、重同步与重连只在 Rust 实现，Kotlin / Swift 应用已接受的信号。工程与生成命令见 `clients.md`「原生移动端」及「原生 iOS」。

### `native/server`（`fluxdown_server`）：**已冻结**，不构建、不发布、不接收改动；headless 由 `fluxdown-agent --server` + `fluxdownd` 承担 → 见本文「Headless 服务器」

### `native/cli`（`fluxdown_cli`，二进制 `fluxdown`）
aria2c 风格。命令：ping/info/add(get)/list(ls)/status(stat)/pause/resume/rm/pause-all/resume-all/queue/watch/**config**(set/unset/get/list/path)。
- **A 模式**（默认）：typed HTTP client（复用 api `routes`+`types`），连运行中的 App/server。
- **B 模式**（`add --local`）：本进程内嵌 `fluxdown_engine::Engine`（`NoopSink`/`NoopSelection`）独立下载至终态，共享同一 SQLite（安装模式）。Ctrl-C → 暂停 + 退出码 7。
- env：`FLUXDOWN_URL`（默认 `http://127.0.0.1:17800`）/`FLUXDOWN_TOKEN`；`--json`；`K/M/G/T` 按 1024 解析；`.no_proxy()` 直连回环。退出码：0/1/2/3/5/7/24/32（aria2 风格，`exit.rs`）。

### `native/nmh`
浏览器 Native Messaging Host **中继二进制**（`com.fluxdown.nmh`）。浏览器 ↔（stdin/stdout 4 字节 LE 长度 + JSON）↔ nmh ↔（每用户 Named Pipe / 私有 UDS）↔ agent。同步单线程；懒连 + 重连；除 `NO_LAUNCH_ACTIONS`（ping/tasks/task_op/open/reveal）外未连接时自动拉起 App（50ms 轮询至 10s）；`warmup` 本地应答重叠冷启动；1MB 帧上限。
- **IPC 端点**（中继 `nmh/src/main.rs`、GPUI `agent/src/nmh.rs` 各自独立推导，测试钉同一组字面量）：Unix `<用户数据目录>/ipc/fluxdown.sock`，`ipc` 目录权限 0700；缺 home 时不可用，不回退共享目录。Windows `\\.\pipe\fluxdown-<编码账户名>`：账户名转小写，`[a-z0-9]` 以外的每个 UTF-8 字节编码为 `_xx`，下划线自身也编码；缺账户名时不可用，不回退旧固定管道名。新中继只连接新端点，不保留旧 socket 符号链接或旧路径回退。
冷启动目标按 `APP_EXE_CANDIDATES` 在 nmh 同级目录查找 `fluxdown-agent`；无 Flutter 本体回退（Flutter 已无桌面发行物）。
- **浏览器注册（agent `nmh::registry`）**：只注册与 `fluxdown-agent` 同目录的 `fluxdown_nmh`（同一次构建，端点与帧协议一致），不回退到其它构建目录；`cargo desktop-dev` 因此一并构建中继。启动自愈在 IPC 端点开始监听后运行：注册指向另一份安装的中继时，按浏览器的方式拉起它发一条 `ping`，连不到本 agent（旧端点/旧帧协议）就改指向本安装；连得到才按路径规则保持先到者（安装版优先于开发构建/临时挂载）。
- macOS home 查询复用 `std::env::home_dir`（HOME 缺失/空时回退 passwd，保留合法非 UTF-8 路径）；NMH 不再依赖 libc，入口 `forbid(unsafe_code)`，不改变 Linux HOME-only 策略。


### `native/daemon` + `native/agent`：设置面 JSON-RPC（GPUI 客户端唯一入口）
方法名、DTO 与错误码全在 `native/protocol`（`method.rs` / `daemon.rs` / `agent.rs` / `daemon_config.rs`）；GPUI 设置页只经 agent `/rpc`（默认 `ws://127.0.0.1:17800/rpc`，实际端点由 bearer 同目录的 `gateway-endpoint.json` 发现），`daemon.*` 由 agent 透明转发。
- 本机协议基线由 `protocol/rpc.rs` 的版本常量控制；新增严格事件枚举（如 `CloudConnectionChanged`）即升版本，拒绝不能解析这些事件的旧进程混用，更新时 UI/agent/daemon 必须一起重启——版本不兼容且对端已通过传输鉴权时，可在 `system.hello` 前发 `system.shutdown` 替换旧进程；新版 agent 对不支持挑战握手的旧 daemon 不发送长期 token，而由 supervisor 终止 stale daemon 后拉起新版本。每进程替换有界。`task_activity.rs` 定义任务运行态与活动 DTO；`daemon.task.activity {taskId, beforeId?, afterId?, limit?}` 查询持久历史，两种游标互斥、页内 ID 升序，返回保留范围、更多页及截断信息。实时 `TaskActivityAdded` 仅在提交后广播，`TaskRuntimeChanged` 同时更新快照。
- **daemon ↔ agent 双向认证**（`protocol/{handshake,digest}.rs`、`daemon/src/{rpc,http}.rs`、`agent/src/daemon_client.rs`）：新版 agent 仅以 `daemon.token` 作 HMAC-SHA256 密钥，不发送长期 token，WS 升级头不带凭据（带 `Origin` 的升级 403）。`system.hello` 之前，agent 发 `system.auth.challenge {clientNonce}` → daemon 回 `{serverNonce, serverProof}` → agent 验证服务端证明后发 `system.auth.prove {clientProof}`。认证前只放行这两个方法；其余（含 hello/shutdown）拒绝并断开；10s 超时、认证中连接最多 16、认证前帧最多 4KiB。daemon 的「握手前 shutdown」指认证后、hello 前；agent 的 UI Gateway 则仍在 hello 前受理已通过升级鉴权的 shutdown。
- **daemon HTTP 会话凭据与旧版兼容**：新版 agent 对 `/blobs`、`/files`、`/exports` 只发送两端各自派生的 `http_credential(token, clientNonce, serverNonce)`，不经 WS 传输，连接断开即撤销；`DaemonClientConfig::http_session()` 无凭据时按 daemon 不可用处理，绝不回退长期 token。daemon 作为校验方仍接受旧 agent 的有效静态 Bearer（WS 升级头与 HTTP），仅为包已更新但旧进程仍常驻时保持可用；新版 agent 不向旧 daemon 降级发送 token。
- **慢方法共享清单**：`protocol/src/method.rs::SLOW_DAEMON_METHODS/is_slow_daemon_method` 是 daemon 与 agent 唯一判定源；daemon 慢调用每连接有界并发（最多 16），agent 放入独立 `DaemonSlow` 通道（最多 8），普通 daemon 命令同道串行以保持顺序，慢网络/安装不阻塞暂停、恢复和设置写入。不要在传输层另建清单；批量 aria2 RPC 与 `/rpc` 多请求并发不是同一契约。
- **daemon 配置键目录 = `fluxdown_protocol::DAEMON_CONFIG_FIELDS`**（键、类型、范围、枚举、默认值、只读）。daemon `config.rs::validate_config_patch` 直接用 `normalize_daemon_config_patch` 校验；`public_config_values` 按 `is_public_daemon_config_key` 投影（含只读键 `domain_conn_caps`、`bt_tracker_sub_cache/updated_at`、`ed2k_server_sub_cache/updated_at`）。新增 daemon 设置 = 在目录加一行 + `actor.rs::apply_live_config` 按需 live-apply。`bt_seed_enabled`/`bt_auto_reseed` 落库前转 `"1"/"0"`（引擎按 `!= "0"` 读）。
- daemon 设置相关方法：`daemon.config.get/patch/proxyTest`、`daemon.config.connPolicy`（`domain_conn_caps` 有效条目数）/`clearConnPolicy`、`daemon.siteAuth.list/delete/clear`（`site_auth_credentials`，列表永不回传密码）/`match {url}`（按引擎 `site_key` 匹配单站点凭据、含明文密码，仅供本机官方 UI 新建下载表单回填）、`daemon.webhook.get/test/simulate/clearDeliveries`、`daemon.bt.trackerSubscription.refresh`、`daemon.ed2k.serverSubscription.refresh`、`daemon.component.*`、`daemon.plugin.*`（含 `daemon.plugin.auth` 的 `begin/poll/cancel/logout/status` 登录状态机——`logout` 在插件禁用时也放行，走宿主兜底删除凭据不进 JS；`poll` 回包省略 `challenge`/`challengeType` 时客户端保留上一帧）、`daemon.diagnos...
- agent 设置相关方法：`agent.preferences.patch {values, sync?}`（云同步目录键 `sync=true` 走同步链路——daemon 键也由 agent 转写 daemon；设备本地键 `sync=false`）、`agent.gateway.get/patch`（功能开关 + `lanEnabled`（下次启动生效）/ `port`（验证新 API/RPC 服务后立即生效）+ `regenerateUserToken`；状态 `port` 是唯一已生效监听值；端口占用 / 启动或保存失败分别返回 `gatewayPortInUse` / `gatewayRestartFailed` 并保留原服务与配置；server / 环境固定监听时 `portEditable=false` 并拒绝端口修改）、`agent.platform.integrationGet/setAutostart/setFileAssociation/setUrlProtocol/openPath`（关联 / URL scheme 注册目标 = 同级 `fluxdown-desktop`，macOS 需在 `.app` 内；开机自启注册 **agent 自身** `--autostart`，旧版指向桌面的条目在 agent 启动时自动改写，只改启动目标、不改系统级启用状态，见 clients.md「开机自启」）、`agent.diagnostics.run/repair/logPaths/exportLogs`（结构化 Doctor：check id / hint / repair 稳定字符串，UI 映射 `doctorCheck*/doctorHint*/doctorAction*` 文案）、`agent.update.check`、`agent.power.arm {delaySecs}`（无活跃任务时返回 `{armed:false}`）/`agent.power.disarm`、`agent.capture.submitTorrentFile {path}` 与 `agent.plugin.installFile {path}`（agent 读文件 → daemon `/blobs/*` → 建任务/装插件；GPUI 不直连 daemon HTTP）。
- agent 系统文件图标 `agent.platform.fileIcon {extension, path?, size}` → `{png}`（base64 PNG，`size` 限 16..=256；`native/agent/src/platform/file_icon.rs`，`desktop` feature，headless / server 模式 Unsupported）：按扩展名取（虚拟文件名 `file.<ext>`，文件不必存在），只有 `FILE_ICON_PER_FILE_EXTENSIONS`（`exe`/`ico`）且 `path` 为存在的绝对路径、扩展名一致时按文件取（Windows 失败退回按扩展名）；`.lnk`/`.url` 刻意排除（图标路径可指向远程共享 → NTLM 泄露）。Windows = 专用 STA 工作线程 `SHGetFileInfoW` + 系统图像列表（SMALL/LARGE/EXTRALARGE，线程内惰性缓存 IImageList；先释放接口再撤销 COM，初始化失败不渲染）+ `GetDIBits`，预乘后 Lanczos3 缩放；macOS = 专用线程 + `autoreleasepool`，`NSWorkspace.iconForFile/iconForFileType` 画进精确像素 8-bit `NSBitmapImageRep` 导出 PNG（勿用 `TIFFRepresentation`：全尺寸表示数十 MB 且为 16-bit float）；Linux = `MainContext::invoke` 投递到 tao/GTK 主线程（`gio::content_type_guess` → `IconTheme::lookup_by_gicon`），限时 2s，GTK 未初始化 Unsupported。网关为它单开 `Lane::Icon`，首屏一批图标请求不阻塞其他本机 RPC。
- 平台 FFI 所有权：macOS `platform/macos_cf.rs` 集中 CF/LaunchServices 获取、借用和释放，字符串/数组 owner 私有且分型，对外只传 Rust 字符串；Windows Shell 定位的 COM/PIDL 均 RAII，STA/WinRT apartment 守卫禁止跨线程移动。原生通知遵守相同约束，不能为去 unsafe 回退已废弃系统通知接口。
- agent 云链路（`native/agent/src/{cloud,remote,sync,device_meta,device_identity,state}.rs`）：**错误** `CloudError::to_rpc_error` 把云端 `code` 映射为 `StateStore::persist(&Mutex<AgentState>)` 持锁只序列化、写盘按代际排序（旧快照不覆盖新快照）；Windows ACL 只在打开数据目录时一次性设置（可继承），保存时不再 spawn `whoami`/`icacls`；`agent-state.json` 解析失败 → 隔离为 `agent-state.corrupt-<ts>.json`（保留最新 3 ### 云设备在线通道

`RemoteTaskService` 拥有设备在线通道；登录会话和配置同步不能替代在线判定。SSE 读流/空闲检测、心跳、串行业务处理属于同一个可取消生命周期，任务快照失败独立重试，不再阻断 SSE 建连。SSE 等待响应头有超时，登出、手动重连及关停会取消旧生命周期。

账号作用域请求使用 `cloud::RequestEpoch` / `CloudApi::at_epoch` 绑定发起时的会话；获取 token、HTTP 响应及最终状态写入都核验代际，最终写入与事件投影在同一状态锁内完成。退出后重登相同 UID 也属于新代际，不能仅按 UID 判断请求仍有效。旧响应的 `session_changed` 不表示当前会话过期，不得据此退出新账号。

`CloudConnectionDto` / `CloudConnectionChanged` 是仅在内存中的运行态。`connected` 需要 SSE 建立、首次心跳成功及心跳后的设备名册刷新成功；名册失败进入 `reconnecting` 并独立重试，不能依赖另一次上线事件才能恢复。PC/Web 共用此投影，把失去新鲜度的设备在线状态显示为未知。`agent.remote.reconnect` 的 `{accepted:true}` 只代表接受请求，普通 `agent.device.list` 不打断健康连接。

事件业务队列有条数与单行大小组合上界，满时背压读流，不可丢弃命令后假设快照能恢复（pause/resume 与 deleteFiles 不是可重放状态）。resync 与普通事件按 FIFO 处理；EOF/心跳失败先停止读流并排空已接收事件，再重连，退出或账号失效仍可直接取消。主动背压不算网络空闲，心跳和会话取消仍独立。重新连接 RPC 走本地请求通道，不排在慢云请求之后。

FluxCloud 对没有任务 SSE 的心跳返回 `409 presence_connection_missing`：按 resync 短暂停后重建事件流，不退出登录，也不误报云不可达。成功心跳仍为 204；在线必须有活跃 SSE，不能靠心跳凭空创建。FluxCloud 的 presence 和事件 hub 当前限单活进程部署，反代配置与验证见 FluxCloud `README.md`；客户端无法用本地标记修复服务端分流或代理拦截。

## Headless 服务器（`fluxdown-agent --server` + `fluxdownd`）

入口 `native/agent/src/main.rs` 的 `--server` → `server_mode::run_blocking` → `runtime::run_with(.., Some(ServerRuntime))`。agent 在同目录拉起 `fluxdownd`（`supervisor.rs`，继承环境 + `with_extra_env` 追加 `FLUXDOWN_DEMO_URL`），经 loopback `ws://127.0.0.1:17801/rpc` 调 daemon。Gateway listener = `fluxdown_api::server::api_router(AgentApiHost)` + `/rpc` + `server_mode::router`（setup / `/api/web/*` / demo / SPA fallback）。

- **env**（`server_mode.rs::ServerConfig::from_lookup`）：`FLUXDOWN_BIND`（默认 `0.0.0.0:17800`，允许非回环，不看 `lan_enabled`）、`FLUXDOWN_TOKEN` + `FLUXDOWN_TOKEN_FORCE`（预置访问密钥；FORCE 每次启动覆盖；不过 `validate_access_key` 则忽略并告警）、`FLUXDOWN_WEBROOT`（可选磁盘覆盖）、`FLUXDOWN_LANG`（`/ping.language` 回退）、`FLUXDOWN_DEMO`/`FLUXDOWN_DEMO_URL`、`FLUXDOWN_ALLOW_LOCAL_PLATFORM`（真值为 `1`/`true`/`yes`/`on`；显式把所有已鉴权连接视为本机来源，只额外放行打开 / 定位任务产物，等同允许远程用户触发服务器 OS 打开文件，默认勿开）。daemon 读：`FLUXDOWN_DATA_DIR`（引擎数据根；agent 状态在 `<root>/agent`）、`FLUXDOWN_DATABASE_URL`（`sqlite:`/`postgres://`）、`FLUXDOWN_SAVE_DIR`（仅 `default_save_dir` 未设置时播种）、`FLUXDOWN_DEMO_URL`（`daemon.task.create` / `daemon.group.create` 精确匹配守卫）。**局域网设备互联（L1）由 agent 实现**（`native/agent/src/link.rs` + `link/{service,storage}.rs`，协议本体在独立 crate `native/link` = `fluxdown_link`；引擎只保留 Db 存储后端 `fluxdown_engine::link::DbLinkStorage` 给 Flutter hub / 旧 server）：`FLUXDOWN_MDNS`（假值 = 不 mDNS 广播，配对码 + 手动地址仍可用）、`FLUXDOWN_LINK_NAME`（局域网里显示的设备名；缺省 server 模式 `FluxDown Server`、桌面为设备名）**已恢复生效**；新增 `FLUXDOWN_TRUSTED_PROXIES`（逗号分隔反代 IP，仅这些 + 回环对端才采信 `X-Forwarded-For`/`X-Real-IP` 做配对猜码节流分桶）。网关只监听回环（桌面默认 `lanEnabled=false`）时：配对码结果 `addresses` 为空、不广播、不自报回连地址；`--server` / `lanEnabled` 正常。配对地址支持 `host` / `host:port` / `http(s)://host[:port][/base]`（反代 / https / 子路径），非 FluxDown 的 4xx / 重定向 / HTML → `pairingNotFluxDown`，网络失败 → `pairingPeerUnreachable`。数据面：`POST /api/v1/link/tasks`（下发）与 `/api/v1/link/info`（经已认证链路交换默认目录 / 路径风格，旧对端 404 → 视为未知），两者都免 management 开关（`route_group_guard` 白名单）。接单目录回退：非本机风格绝对路径 → daemon 默认目录，带目录建任务失败 → 去掉目录重试。
- **访问密钥** = `AgentState.gateway_user_token`（热更新 `TokenCell`，兼容 API 与 Web 共用）。策略单一事实源 `server_mode.rs::validate_access_key`（ASCII 可见字符、8–128 位、字母+数字），Web 镜像 `web/src/lib/token-policy.ts`；server 模式下 `agent.gateway.patch.userToken` 不能写空/弱密钥（否则匿名 setup 重新打开）。旧 server 数据目录的 `local_server_token` 与开关由 `link::migrate_legacy_state` 导入，无需手工迁移。全新安装首次运行开启 takeover/jsonrpc/api/mcp 分组。
- **首次设置门禁**（`runtime.rs` 的 `require_token=true` + `api/src/server.rs::route_group_guard`）：访问密钥为空时，`/download`、`/download/batch` 与 `/jsonrpc`（POST/WS 升级）返回 403 `setup required: set the access key first`，即使 aria2 名单方法也不可达；管理 API/MCP 本就拒绝空 token。Web SPA、`/ping` 与 setup 引导接口仍可用，初始化就绪前 setup 可能 503。headless 不自动补桌面暴露面的 token，首次设置前 aria2 与接管不可用。
- **路由**（server 模式专有）：免鉴权 `GET /api/v1/setup/status` → `{setupRequired,minLength}`、`POST /api/v1/setup {token}`（仅密钥为空时，已设 409；daemon 就绪 + 迁移完成前 503）；`/rpc` 浏览器鉴权 = 子协议 `fluxdown.rpc.v1` + `fluxdown.token.<base64url 无 padding>`（Bearer 也接受 agent.token 或访问密钥），带 `Origin` 时须与 `Host`（或 `X-Forwarded-Host` 首段）同源否则 403；浏览器文件面（Bearer 或 `?token=`）：`POST /api/web/blobs/{torrents,plugins}`（转发 daemon blob，4 MiB）、`GET /api/web/files/tasks/{id}`（流式转发已完成文件）、`GET /api/web/exports/{id}`（daemon 诊断 JSON）、`GET /api/web/logs/export`（日志 zip）；演示模式 `GET|HEAD /demo/file`（64 MiB 确定性流、Range、1 MiB/s）。其余 GET/HEAD → SPA。
- **Web UI 内嵌**：`web-ui` feature 下 `native/agent/build.rs` 递归嵌入 `FLUXDOWN_EMBED_WEBROOT`（缺省 `web/dist`），`web_assets.rs` 托管（强 ETag + 304；HTML no-cache、Rollup 哈希文件名 immutable 一年、其余短缓存；未命中回 `index.html`；无 Range；未嵌入 503 自解释页）。改前端须先 `cd web && bun run build` 再重编 agent。
- **进程语义**：server 模式不启 NMH / 不做自启迁移 / 不注册关联；`agent.platform.openTask` / `revealTask` 只对本机来源连接放行（`ServerHandle::local_platform_permitted`：环回 TCP + 转发链每跳环回 + 所有 `Host` / `Origin` / `X-Forwarded-Host` / `Forwarded` authority 为字面 localhost / 环回，或显式 `FLUXDOWN_ALLOW_LOCAL_PLATFORM`），建连时判定一次，放行的连接在 `system.hello` 额外带 `agent.openTaskFiles` 能力（桌面宿主恒带，嵌入式移动宿主不带），Web 据此显示「打开文件 / 打开所在文件夹」；其余 `agent.platform.*` 返回 Unsupported。同机反代的公网域名不会自动获得该能力。SIGTERM/SIGINT 走 `Lifecycle::request_quit`（先关停 daemon 再退出，二次信号强制退出）；stderr tracing（`RUST_LOG`）。Docker 用 tini 做 PID 1。Windows 发布构建带 `windows_subsystem = "windows"`，`--server` 无控制台输出。
- **空闲静默（NAS 硬盘休眠）**：无活动/排队任务、无做种、无到期 RSS、无客户端主动请求时，daemon/agent 不得周期性读写 save_dir 与 data_dir（不 fsync 的写也会被内核回写唤醒机械盘）。落点：daemon 定时文件跟踪扫描受 `idle_file_scan`（默认关，旧库经标记键 `migration_idle_file_scan_off` 一次性迁移为关）经 `should_run_idle_scan()` 门控，客户端获焦 / 页面可见时经 `daemon.task.rescan` 补扫（GPUI `RescanThrottle` ↔ Web `rescanThrottle.ts`）；做种时长仅随上传增量 / 状态迁移 / 关机顺带落库，兜底 30 分钟；DHT dump 30 分钟；仅因暂停的未完成 BT 任务保活的会话 15 分钟后释放；SQLite 池常驻 1 连接不回收（避免 `-wal/-shm` 反复删建）；CDN 配置下发比对后才写、空闲 peek 不读库、agent 未登录不上报；RSS 无语义变化的拉取不落库（运行态以内存为准，`daemon.rss.listSources` 经 actor 重读库并叠加内存运行态）。Doctor `disk_sleep` 检查列出当前阻碍项（做种、RSS、空闲扫描）。部署建议：`/data` 放 SSD / 缓存池。
- **Doctor 动态权限探测**：`agent.diagnostics.run` 经 agent 专用的 `daemon.diagnostics.probe`（`require_local_agent`，慢方法）让 daemon 在下载实际发生的进程里对默认 / 队列 / 启用的 RSS 源 / 分类（agent 经 `extraDirs` 追加）保存目录与 daemon 数据目录做「创建→写入→fsync→读回→重命名→删除」往返（不存在的目录在最近的已存在上级探测，不创建目标；`/Volumes`、`/media` 等挂载容器上被拒归为卷未挂载；结果带 `osError`），并以 20s 时限运行已解析到的 ffmpeg / ffprobe / yt-dlp 版本命令（`components::exec_probe` 区分启动被拒与运行失败）。只由用户触发，不属于周期任务。桌面宿主另报 `nmh_launch`（像浏览器那样拉起已注册入口并经它 `ping` 到 agent：Unix 执行 `fluxdown_nmh.sh`，Windows 经 `cmd.exe /d /c`）、`nmh_policy`（Windows Chrome / Edge `NativeMessagingUserLevelHosts` / `Blocklist` / `Allowlist` 与 `DisableCMD`，只报告不绕过）、`nmh_ownership`（Unix 属于其他用户的注册文件）、`elevated_run`（Unix 以 root 运行）、`autostart`、`notifications`；Web 隐藏这些桌面专属检查。实现：`native/daemon/src/doctor_probe.rs`、`native/agent/src/diagnostics.rs`。
- **Doctor 修复与提权契约**（`native/agent/src/{permission.rs,diagnostics/repair.rs}`）：修复只在用户点按钮时发生（`agent.diagnostics.repair`）。**提权只做「释放」**——把被 root / 管理员占住的路径还给当前用户（类 Unix 改回属主：FluxDown 自有目录递归、家目录内只改该目录；家目录外的共享目录不抢属主，只加当前用户的可继承 ACL：Linux `setfacl -P`、macOS `chmod -h +a`、Windows `icacls /grant *SID:(OI)(CI)M /L`）；提权命令一律不跟随符号链接（`chown -h` / `-R -h`，释放脚本遇到符号链接目标直接拒绝）。属于当前用户、只是缺权限位的目录不提权，普通权限 `chmod u+rwx`（NMH 目录同理，只有属主不是自己的目录才请求授权）；真正的重写 / 注册回到普通权限完成，修完重新探测，仍未通过报 `repairIncomplete`。提权外壳：Linux `pkexec`、macOS `osascript … with administrator privileges`、Windows PowerShell `.NET ProcessStartInfo{Verb=runas}`（只有它能把 UAC 取消识别为 1223）；Windows 先以普通权限试 `icacls`，被拒才转 UAC，超时（大目录传播继承项）直接报错不转 UAC。命令是固定模板，路径只作参数（PowerShell 经环境变量传入），目标路径取自重新探测；根目录 / 家目录及其上级 / 系统与软件安装树（Linux `/opt` `/snap` `/nix` `/usr` `/var` …，macOS `/opt` `/nix` `/Library` …）/ 挂载容器本身（`/mnt` `/media` `/srv` `/run/media` `/Volumes`，其中的卷按共享目录处理）拒绝。提权进程不创建任何 FluxDown 文件或注册项；不写 HKLM、不改组织策略与 Defender 配置（只引导用户去系统设置）。`--server` 不提权：`server_mode_denies` 拒绝 `fix_dir_access` / `enable_autostart` / `open_settings` / `test_notification` 与 NMH / 关联动作；`fix_component`（daemon 的 `daemon.diagnostics.fixComponent` 补托管组件执行位）在 headless 仍可用。失败原因 `ErrorReason::{ElevationCancelled, ElevationUnavailable, RunningElevated, RepairIncomplete, RepairNotApplicable}`，GPUI / Web 在 Doctor 页就地展示。
- **兼容 API**：`AgentApiHost`（`native/agent/src/api_host.rs`）转发 daemon RPC 实现 `ApiHost` 全部核心方法（任务/组/RSS/插件/市场/站点凭据/aria2 WS 通知经 `task_events.rs`）；旧 server 独有的扩展 REST（`/api/v1/config`、队列增删改、stats、fs/list、components、webhooks、logs、token/regenerate、`/api/v1/ws`）已**废弃**，管理面只走 `/rpc`。

**分发目标**（`fluxdown-agent` + `fluxdownd` 同目录，入口 `fluxdown-agent --server`，镜像名仍 `ghcr.io/zerx-lab/fluxdown-server`；资产随统一 `vX.Y.Z` release 发布，历史版本在 `server-v*` release）：Docker（amd64+arm64）、群晖 SPK、QNAP QPKG、OpenWrt IPK+LuCI、Unraid CA 模板、CasaOS。脚本在 `packaging/`、`promotion/`、`docker/`。

## 应用内更新（`native/agent/src/update/`，桌面、headless 与原生 Android 共用）

状态归 agent：`UpdateService`（`update/mod.rs`）独占 `UpdateStatusDto`，经 `AgentSnapshot.update` + `AgentEvent::UpdateChanged` 推送（协议 v8）；方法 `agent.update.{check,download,install,cancel}` 都返回 `UpdateStatusDto`。UI 只渲染状态、发请求，GPUI（`crates/settings/src/update_view.rs` 判定 + `about.rs`、`crates/app/src/update_notices.rs` 通知）与 Web（`web/src/lib/update.ts` ↔ 同一套阶段 / 按钮 / 文案键规则，`shell/UpdateStatus.tsx` 横幅与重启遮罩）逐条对齐。

- **宿主**：`UpdateService` 内部区分 agent 宿主（状态进事件总线、本进程替换文件后重启）与委托宿主 `UpdateService::delegated` + `UpdateDelegate`（原生 Android：状态与「已校验安装包就绪」交给 App，App 经 PackageInstaller 安装，失败 / 取消经 `install_failed` 回报）。两者共用同一状态机、检查、续传下载与 `pending.json` 对账，**禁止在 Kotlin 另写一套**。
- **检查**（`update/release.rs`）：`/api/release?channel=` 按安装形态取桌面顶层资产、`server.assets` 或 `mobile.assets`；更新包 URL 恒为 `/api/download/<资产名>?tag=<tag>`（不带 tag 会拿到「最新稳定版」，与检查结果竞态）。校验和取组件哨兵 `SHA256SUMS-app.txt` / `SHA256SUMS-server.txt` / `SHA256SUMS-mobile.txt`，回退 `SHA256SUMS.txt`；没有该资产的条目 → `manualReason=noAsset`，只给手动下载。**发布流水线改资产命名或哨兵格式必须同步这里与官网 `/api/release`。**
- **官方站点（域名迁移）**：`DEFAULT_API_BASES = [fluxdown.zerx.dev, fluxdown.com]`，检查时错峰竞速（上次成功的站点先发，3s 内无结果或已失败才发下一个，首个成功者胜出），胜出站点用于同一轮的更新说明、校验和、更新包与 `releasePageUrl`；可信下载域含 `zerx.dev` / `fluxdown.com` / GitHub。两域任一可用即可更新；迁移完成后调换数组顺序即可，旧域下线不影响已发布客户端。
- **自动行为**：偏好 `general.auto_check_update`（默认开）→ 启动 30s 后首检、之后每 6h（只走网络，不碰磁盘，符合空闲静默）；可一键更新时自动后台下载 + 校验（`<agent 数据目录>/updates/<版本>/`，`.part` + Range 续传）→ `ready`。永不在无用户点击时安装。用户取消某版本的下载后该版本不再自动下载。
- **安装形态**（`update/install/detect.rs`，启动时检测一次）：Windows 安装版 / 便携版（`portable` 标记）、macOS `.app`、Linux AppImage / deb / Arch / 便携 tar.gz、headless 二进制包；资产按**硬件**架构选（x64 Windows 构建跑在 ARM64 上读注册表 `PROCESSOR_ARCHITECTURE` 换 arm64 包，Rosetta 下的 x64 macOS 构建经 `sysctl hw.optional.arm64` 换 arm64 包）。不能自更新：未注入 `FLUXDOWN_APP_VERSION` 的开发构建（`unofficialBuild`）、`FLUXDOWN_INSTALL_SOURCE=docker|synology|qnap|openwrt` 或 `/.dockerenv`（`managedPackage`，Dockerfile 与 NAS 启动脚本已设置）、目录不可写、deb/Arch 无 `pkexec` 或图形会话、macOS App Translocation / 从 DMG 运行、macOS 当前 bundle 无 TeamIdentifier。
- **安装与重启**（`install/` + `restart.rs`）：先写 `updates/pending.json`，在旧进程仍运行时替换文件（失败整体回滚、原程序可用）：便携 / 服务器包解压（拒绝穿越与链接条目，跳过 macOS AppleDouble `._*` / `__MACOSX`），只替换包内存在的文件，旧文件改名为 `*.fluxdown-old`（Windows 允许改名运行中的 exe；`portable_data/` 永不触碰）；AppImage 同目录临时副本 rename 覆盖；deb/Arch 经 `pkexec` 调 apt-get(dpkg) / pacman；macOS 挂载 DMG（或 `/usr/bin/tar` 解 tar.gz）→ `ditto` 到同卷暂存 → `codesign --verify --deep --strict` 且 TeamIdentifier 与当前一致 → 两次 rename 交换 bundle。随后 `Lifecycle::request_restart` 走完全退出（先停 daemon），**agent 运行期完全结束后** `main` 执行计划：Windows 安装版静默跑安装器（`/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SP- /LOG=`，`setup.iss` 静默 `[Run]` 带 `--after-update` 拉起桌面）；其他桌面形态分离启动 `fluxdown-desktop --after-update`（macOS `open -n FluxDown.app --args --after-update`，AppImage `$APPIMAGE --after-update`）；headless 在 Unix 上 `exec` 原路径原 argv（PID 不变，systemd / tini / 终端照常），Windows 分离重启。
- **关闭原因**：桌面形态的更新重启仍是 `service-quit`（桌面退出，由计划重新拉起）；headless 为 `service-restart`（`CLOSE_REASON_SERVICE_RESTART`），浏览器保持重连，握手 `serviceVersion` 变化即 `location.reload()`；握手 `protocolIncompatible` 时 60s 内只自动刷新一次（覆盖 Docker / NAS 跨协议升级）。
- **对账**：下次启动 `pending.json` 目标版本 = 当前版本 → 删除 `updates/`；否则 `failed` + `installIncomplete`。改名残留在启动时清理。桌面 `--after-update` 会等待旧实例释放单实例锁（≤30s）而非把激活转发给正在退出的旧进程，就绪后提示「已更新到 vX」。
- **本地冒烟**：仅调试构建认 `FLUXDOWN_UPDATE_BASE_URL`（覆盖官网地址并跳过可信域校验），配合 `FLUXDOWN_APP_VERSION=<旧版本>` 构建、本地假 `/api/release` + `/api/download` 即可跑通 headless 检查 → 下载 → 替换 → `exec` 重启；另起实例时用 `FLUXDOWN_DAEMON_URL` 换 daemon 端口，避免连到本机正在运行的 daemon。
- **原生 Android**（`native/mobile/src/update.rs` 的 `AppUpdater`，经 `FluxCore::app_updater` 取得，进程内唯一，与主机会话无关——远端模式下更新的也是 App 本身）：资产按 `Build.SUPPORTED_ABIS` 第一个有分包的 ABI 取 `android_{arm64,armv7,x64}`，兜底 `android_universal`（`InstallTarget::android`）；`versionName` 不可解析 → `unofficialBuild`；App 侧判定商店安装 → `managedPackage`、可调试 / 签名证书非官方 → `unofficialBuild`。Rust 不起周期任务，调度归 App（前台 6h 节流 + JobScheduler 每日后台检查，非计量网络才自动下载），安装前 App 再校验 APK 包名 / 签名证书 / versionCode，不符按 `verify` 回报并丢弃该包。Kotlin 判定规则镜像 `update_view.rs`（见 `.omp/knowledge/clients.md`）。
